Part 0

Conway’s Game of Life

A grid of cells, two rules, and an unbounded variety of behaviour.

The Game of Life

Two rules on an infinite grid

Each cell of $\mathbb{Z}^2$ is alive or dead. Every generation, all cells update at once, by counting their 8 neighbours:

Birth

A dead cell with exactly 3 live neighbours becomes alive.

Survival

A live cell with 2 or 3 live neighbours stays alive; otherwise it dies.

This is the rule B3/S23, devised by John Conway (1970). Start from a finite pattern; the question is what it does forever.

Try it: click cells to toggle them (pause first), drag to pan, scroll to zoom. The pattern shown is the R-pentomino: 5 cells that take 1103 generations to settle.

The Game of Life

Still lifes, oscillators and spaceships

The block and the beehive never change; the blinker has period 2.

The glider: after 4 generations it is itself, moved one cell diagonally.

  • Still life: unchanged by a step (block, beehive, eater).
  • Oscillator: returns after $p$ steps (blinker, $p = 2$).
  • Spaceship: returns translated (glider: period 4, moves $(1,1)$).
  • Gun: emits spaceships forever (Gosper, 1970).
  • With guns, gliders and eaters one can wire signals, gates and memory.
  • Berlekamp, Conway and Guy (Winning Ways, 1982) sketched why Life is universal: it can simulate counter machines.

Goal

The headline theorem

There is a cell $c$ such that no algorithm decides, given a finite starting pattern, whether $c$ is ever alive.

/-- **Undecidability of the Game of Life.** There is a cell `c` such that it is not computable,
from the finite initial pattern, whether `c` is alive at some generation. -/
theorem exists_not_computablePred_everAlive' :
    ∃ c : Cell, ¬ ComputablePred fun w : WindowData => EverAlive c w.cells :=
  exists_not_computablePred_everAlive_of_decSepRest fun _ hp _ => dsep_rest hp

Kernel · Kernel/Life.lean

The rule, as a definition

Definitions

abbrev Cell : Type := ℤ × ℤ

def nbrs (c : Cell) : Finset Cell :=
  (Finset.Icc (c.1 - 1) (c.1 + 1) ×ˢ Finset.Icc (c.2 - 1) (c.2 + 1)).erase c

def liveNbrs (S : Finset Cell) (c : Cell) : ℕ := ((nbrs c).filter (· ∈ S)).card

structure Rule where
  birth : Finset ℕ
  survive : Finset ℕ
  zero_notMem_birth : 0 ∉ birth

def conway : Rule := ⟨{3}, {2, 3}, by simp⟩

def Rule.step (R : Rule) (S : Finset Cell) : Finset Cell :=
  (S ∪ S.biUnion nbrs).filter fun c =>
    if c ∈ S then liveNbrs S c ∈ R.survive else liveNbrs S c ∈ R.birth

def Rule.evolve (R : Rule) (n : ℕ) (S : Finset Cell) : Finset Cell := R.step^[n] S
  • A configuration is a finite set of live cells (Finset Cell); step is computable.
  • Birth at 0 neighbours is excluded, so finite stays finite.
  • An independent set-level specification stepSet states the rule cell by cell.

Correctness

theorem Rule.mem_step {R : Rule} {S : Finset Cell} {c : Cell} :
    c ∈ R.step S ↔
      (c ∈ S ∧ liveNbrs S c ∈ R.survive) ∨ (c ∉ S ∧ liveNbrs S c ∈ R.birth)

theorem Rule.coe_step (R : Rule) (S : Finset Cell) :
    (R.step S : Set Cell) = R.stepSet (S : Set Cell)

Certificates · Certificates/LifeSim.lean, BoxCert.lean

Checking thousands of generations, without decide

  • A window ofRows x y rows: bit $j$ of row $i$ is the cell $(x + j, y + i)$.
  • One generation of a row is a fixed bit-parallel adder formula of the rows above, at and below.
  • A certificate is an explicit proof term with one kernel fact per row per generation; untrusted code proposes it, the kernel re-checks every leaf with GMP arithmetic.
  • life_cert, life_eval, life_reaction (with a footprint box per generation); long runs are emitted by Python into Gen/* files.
def nextRow (u m d : ℕ) : ℕ :=
  let su := xor3 (u <<< 2) (u <<< 1) u
  let cu := maj3 (u <<< 2) (u <<< 1) u
  let sd := xor3 (d <<< 2) (d <<< 1) d
  let cd := maj3 (d <<< 2) (d <<< 1) d
  let sm := (m <<< 2) ^^^ m
  let cm := (m <<< 2) &&& m
  let ones := xor3 su sd sm
  let carry := maj3 su sd sm
  let odd := (cu ^^^ cd) ^^^ (cm ^^^ carry)
  let two := (cu &&& cd) ||| (cm &&& carry)
  let exactlyOne := odd ^^^ (odd &&& two)
  exactlyOne &&& (ones ||| (m <<< 1))

Components · Locality.lean, Reactions.lean, Network.lean

Locality: far-apart patterns evolve independently

  • Life has a speed of light: after $n$ steps a cell depends only on cells within distance $n$.
  • So patterns that stay at distance $\ge 3$ evolve independently, and 3 is sharp.
  • A Reaction P Q n F: $P$ becomes $Q$ in $n$ generations, staying inside the footprint $F\,i$ at every generation $i$.
  • Reactions compose in parallel (footprints far apart), in sequence and under translation; a Proc list is one segment of a big circuit.

Definitions

def FarApart (r : ℕ) (A B : Set Cell) : Prop := ∀ a ∈ A, ∀ b ∈ B, ¬ Near r a b

structure Reaction (P Q : Finset Cell) (n : ℕ) (F : ℕ → Set Cell) : Prop where
  evolve_eq : conway.evolve n P = Q
  subset : ∀ i ≤ n, (conway.evolve i P : Set Cell) ⊆ F i

structure Piece where   -- an idle period-30 part of the machine
  rest : Finset Cell
  a : ℤ
  b : ℤ
  lo : ℤ
  hi : ℤ
  rest_reaction : Reaction rest rest 30 (fun _ => Box a b lo hi)

Correctness

theorem Rule.evolve_union_of_forall_sep (R : Rule) {n : ℕ} {S T : Finset Cell}
    (h : ∀ k < n, Sep 2 (R.evolve k S) (R.evolve k T)) :
    R.evolve n (S ∪ T) = R.evolve n S ∪ R.evolve n T

theorem Reaction.par {P Q P' Q' : Finset Cell} {n : ℕ} {F F' : ℕ → Set Cell}
    (h : Reaction P Q n F) (h' : Reaction P' Q' n F')
    (hsep : ∀ i < n, FarApart 2 (F i) (F' i)) :
    Reaction (P ∪ P') (Q ∪ Q') n (fun i => F i ∪ F' i)

theorem Reaction.seq {P Q R : Finset Cell} {n m : ℕ} {F G : ℕ → Set Cell}
    (h : Reaction P Q n F) (h' : Reaction Q R m G) :
    Reaction P R (n + m) (fun i => if i ≤ n then F i else G (i - n))

theorem Reaction.parList {n : ℕ} (l : List (Proc n)) (h : l.Pairwise Proc.Indep) :
    Reaction (Proc.start l) (Proc.stop l) n (Proc.foot l)

The Gosper glider gun

36 cells, period 30: one new glider every 30 generations, forever.

On finite configurations a gun is not periodic (its population grows), so the right statement is an invariant for every $n$: the gun plus $n$ gliders.

Sliding block memory

Pull: a 2-glider salvo moves the block from 3 to 2.

Components · Diagonal.lean, Salvos.lean, DiagSmall.lean

The register diagonal: a block and a queue of salvos

  • An instruction ends when the control glider reaches the next unit, but a salvo needs about $4k$ generations to reach the block.
  • So at an instruction boundary a register is a block plus a queue of salvos still in flight on its diagonal.
  • The register’s value is the block position plus the moves still in flight: K + qMove q.
  • Main facts: the diagonal stays in a strip forever, and after diagTime the block sits at its value.
structure Salvo where        -- fields abridged
  S : Finset Cell
  d : ℤ
  n : ℕ
  four : conway.evolve 4 S = translate (1, 1) S
  hz : Reaction (S ∪ counter 0) (counter d) n (fun _ => Box za zb zlo zhi)

def flights : List (Salvo × ℤ) → Finset Cell
  | [] => ∅
  | (σ, e) :: q => σ.at e ∪ flights q

def RegS.val (R : RegS) : ℕ := (R.K + qMove R.q).toNat

Correctness

Counter machines

  • Registers $\mathbb{N} \to \mathbb{N}$; instructions inc r, decJz r l, halt: exactly what the Life components provide.

The layout: a program becomes a pattern

  • One unit per instruction (an entry chain of OR gates and a body), one module per register (the circuit, its chains, dispatch stations, line-end eaters) and routes of reflectors between them.
  • Every position is an affine formula in the indices and in global parameters: instructions, registers, callers per register, predecessors per unit. Diagonal coordinates $u = x - y$, $v = x + y$; pitches $\equiv 0 \pmod{30}$.
  • Every piece is a translated, phase-shifted copy of a certified base piece.

def U (p : Program) (r : ℤ) : ℤ := U0 p + PM p * r

structure MState where
  pc : ℕ

  reg : ℕ → RegS

def MState.cfg (s : MState) : Cfg := ⟨s.pc, fun r => (s.reg r).val⟩

def encM (p : Program) (s : MState) : Finset Cell :=
  machAt p s.T ∪ ctrlAt p s.pc ∪ regsAt p s.reg (numRegs p)

def InvM (p : Program) (s : MState) : Prop :=
  s.pc < p.length ∧ s.T % 30 = 0 ∧ (∀ r < numRegs p, (s.reg r).Inv) ∧
    ∀ r, numRegs p ≤ r → (s.reg r).val = 0

def startM (n : ℕ) : MState := ⟨0, 0, fun r => RegS.ofNat (if r = 0 then n else 0)⟩

def machRegion (p : Program) : Set Cell := {c | uMin p - 300 ≤ c.1 - c.2}
  • The encoding is the machine at phase $T$, the control glider at the entrance of unit pc, and every register’s diagonal at its module.
  • The machine state projects onto the counter-machine configuration through the values of the registers.
  • The whole run stays in machRegion, a half-plane in $u = x - y$. The halt cell lies outside it, so it is never hit before the halt.

The theorem

/-- **Undecidability of the Game of Life.** There is a cell `c` such that it is not computable,
from the finite initial pattern, whether `c` is alive at some generation. -/
theorem exists_not_computablePred_everAlive' :
    ∃ c : Cell, ¬ ComputablePred fun w : WindowData => EverAlive c w.cells :=
  exists_not_computablePred_everAlive_of_decSepRest fun _ hp _ => dsep_rest hp
#print axioms LeanTheory.Life.LP.exists_not_computablePred_everAlive'
'LeanTheory.Life.LP.exists_not_computablePred_everAlive'' depends on axioms:
  [propext, Classical.choice, Quot.sound]

What it says

For some cell $c$, the set of finite patterns (encoded as windows of bit rows) from which $c$ is eventually alive is not computable.

What is trusted

Lean’s kernel, the 147-line kernel definition of the rule, and Mathlib’s ComputablePred.

What is not trusted

The Python planners and generators, the layout search, the numerical checks: they only propose; Lean checks.
